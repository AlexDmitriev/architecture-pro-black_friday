## <a name="_3bfxc9a45514"></a>**Функциональные требования**

### <a name="_3bfxc9a45514"></a>**Коллекция Orders**

|**№**|**Действующие лица или системы**|**Use Case**|**Описание**|
| :-: | :- | :- | :- |
|UC1|Клиент, сайт|Создание заказа|Быстрое создание заказов с одновременным списанием остатков *. |
|UC2|Клиент, сайт|Просмотри истории заказов|Поиск истории заказов конкретного пользователя. |
|UC3|Клиент, сайт|Просмотр деталей заказа|Отображение статуса заказа.|

Предлагаемая схема коллекции
```
{
    "id": "uuid",
    "user_id": "uuid",
    "created_at": "timestamp",
    "items": [
        {"product_id": "uuid", "price": "int", "quantity": "int"},
        {"product_id": "uuid", "price": "int", "quantity": "int"},
        {"product_id": "uuid", "price": "int", "quantity": "int"}
    ],
    "status": "enum",
    "price_total": "int",
    "location": "string"
}
```


Предлагаемая стратегия шардирования - hashed по полю user_id, что обеспечит равномерное распределение записей (заказов) по пользователям, быструю выборку как истории заказов, так и выборки заказов по статусам (при наличии необходимых индексов). 

Создание шарда: 
```
sh.shardCollection("shop.orders", { "user_id": "hashed" })
```

Необходимые индексы:
```
db.orders.createIndex({ user_id: 1, status: 1, created_at: -1 })
```

*- списание остатков рассматривается в коллекции products

### <a name="_3bfxc9a45514"></a>**Коллекция Products**

|**№**|**Действующие лица или системы**|**Use Case**|**Описание**|
| :-: | :- | :- | :- |
|UC1|Клиент, сайт|Создание заказа|Частые обновления остатков при покупках.  |
|UC2|Клиент, сайт|Поиск товаров|Поиск товаров по категориям и фильтрация по диапазону цен.|
|UC3|Клиент, сайт|Просмотр деталей товара|Описание товара на странице продукта.|

Предлагаемае схема коллекции
```
{
    "id": "uuid",
    "name": "string",
    "category": "string",
    "price":  "int",
    "stock": [
        {"location": "string", "quantity": "int"},
        {"location": "string", "quantity": "int"}
    ],
    "attributes": [
        {"attr_name": "string", "attr_value": "mixed"},
        {"attr_name": "string", "attr_value": "mixed"},
        {"attr_name": "string", "attr_value": "mixed"}
    ]
}
```


Предлагаемая стратегия шардирования - hashed по полю category, что обеспечит ,быструю выборку товаров по категорями, быстрое обновление остатков **при условии, что в запросе на обновление будет присутствовать category**, т.к. они не раскиданы по шардам, а являются частью карточки товара, а так же фильтрацию товаров по ценам внутри отдельно взятой категории (в запросе пристуствует поле category).

Создание шарда: 
```
sh.shardCollection("shop.products", { "category": "hashed" })
```

Необходимые индексы:
```
db.products.createIndex({ category: 1, price: 1 })
```

### <a name="_3bfxc9a45514"></a>**Коллекция Carts**

|**№**|**Действующие лица или системы**|**Use Case**|**Описание**|
| :-: | :- | :- | :- |
|UC1|Клиент, сайт|Создание корзины|Создание корзины, когда заходит гость или новый пользователь. |
|UC2|Клиент, сайт|Получение корзины|Получение текущей корзины по фильтру { session_id, status:"active" } или { user_id, status:"active" }. |
|UC3|Клиент, сайт|Изменение набора корзины|Добавление или замена товара в корзине.|
|UC4|Клиент, сайт|Удаление товара|Удаление товара из корзины.|
|UC5|Клиент, сайт|Слияние корзины|Слияние гостевой корзины в пользовательскую, если пользователь залогинится|
|UC6|Клиент, сайт|Смена статуса корзины|Отметка корзины как заказанной.|

Предлагаемае схема коллекции
```
{
    "id": "uuid",
    "user_id": "uuid|null",
    "session_id": "uuid|null",
    "entity_id": "type (user | session ) + type_id (user_id | session_id)",
    "items": [
        {"product_id": "uuid", "quantity": "int"},
        {"product_id": "uuid", "quantity": "int"},
        {"product_id": "uuid", "quantity": "int"}
    ],
    "status":  "active | ordered | abandoned",
    "created_at": "timestamp",
    "updated_at": "timestamp",
    "expires_at": "timestamp"
}
```

В первую очередь предлагается ввести дополнительное поле entity_id, которое является составным ключем из типа корзины (session или user) и уникальным идентефикатором сессии, либо пользователя.

Предлагаемая стратегия шардирования - hashed по полю entity_id, что обеспечит ,быструю выборку корзины пользователя исходя из контекста (session или user), для дальнейшей работы с ней.

Массовая выборка записей пользователя не требуется. поэтому нет необходимости шардировать или индексировать по session_id или user_id. 

Создание шарда: 
```
sh.shardCollection("shop.carts", { "entity_id": "hashed" })
```

Необходимые индексы:
```
db.products.createIndex({ entity_id: 1, status: 1, expires_at: 1 })
```
